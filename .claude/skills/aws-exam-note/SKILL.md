# AWS Exam Note — จดเทคนิคสอบจาก practice exam

Input: โจทย์ + เฉลย ("Overall explanation") หนึ่งข้อหรือหลายข้อที่ user วางมา
Output: บทเรียนจากข้อนั้นถูก**ผสาน**เข้า `notes.md` — เอกสารสรุปภาษาไทยไฟล์เดียว
ที่อ่านง่าย มีตารางเปรียบเทียบ มี analogy — **ไม่ใช่** การ append entry รายข้อ
· **ไม่มี quiz** (user ระบุเอง — practice exam คือตัวทดสอบอยู่แล้ว) · หลังสรุป
user ถามต่อได้ คำถามเชิงเนื้อหา = จุดไม่เข้าใจ ต้องจดลง `review-again.md` ทันที

ทำใน main session ได้เลย — เป็นงานจัดเก็บโน้ต ไม่ใช่ lesson/code (ข้อยกเว้น
orchestrator-only ตกลงใน ticket AWS-EN1: หัวข้อ "AWS-EN" ใน `docs/tickets/aws-cert.md`
และ exception bullet ใน CLAUDE.md) โหลด `token-efficiency` skill ก่อนรอบแรกของ session

## ไฟล์ (ใต้ `content/exam-notes/aws-saa-c03/`)

- `notes.md` — เอกสารอ่านหลัก**ไฟล์เดียว** โครงบังคับตามลำดับนี้:
  1. หัวไฟล์: comment `<!-- ids: ... -->` (รายการ id โจทย์ที่สรุปแล้ว) + บรรทัด
     "**สรุปจากการทำโจทย์ N ข้อ:** <ชื่อย่อคั่น ·> — อัปเดตล่าสุด YYYY-MM-DD"
  2. `## ส่วนที่ 1 — เทคนิคอ่านโจทย์` — 1.1 กฎเหล็ก/disqualifier ซ่อนในโจทย์ ·
     1.2 ตารางคำชี้ขาด (MOST xxx) · 1.3 ตารางคำสลับ (ตัวลวง) ·
     1.4 หลักการตัดตัวเลือกเร็ว (principle ตั้งชื่อ bold + อธิบาย)
  3. `## ส่วนที่ k — <หมวดเนื้อหา>` — Storage · Auto Scaling · Identity & Access ·
     Networking · Database · Compute · … (สร้างเมื่อมีเนื้อหาแรก, ลำดับเลขต่อกันไป ·
     **section ใหม่แทรกก่อน `## ศัพท์เบ็ดเตล็ดที่เจอ` เสมอ ห้าม append ท้ายไฟล์** ·
     ห้ามรีนัมเบอร์ section เดิม — กัน diff ยักษ์ในไฟล์ที่อ่านซ้ำทุกวัน)
  4. `## ศัพท์เบ็ดเตล็ดที่เจอ` — ตารางคำที่ไม่เข้าหมวดไหน
  5. `## Checklist ก่อนตอบทุกข้อ` — **ต้องเป็น section สุดท้ายเสมอ**
- `review-again.md` — จุดที่ user เคยไม่เข้าใจ เรียงตามตัวนับ "เจอซ้ำ" มาก→น้อย

## ขั้นตอนต่อ 1 รอบ ingest

1. แยก input เป็นรายข้อ · ตั้ง id ขึ้นต้นด้วย provider เสมอ: `TD-set3-Q17` ถ้า user
   แนบเลขชุด/ข้อ ไม่มีก็ `TD-YYYYMMDD-<slug สั้น>` — ห้ามหยุดถาม
2. อ่าน `notes.md` **ทั้งไฟล์** (ต้องเห็นโครงทั้งหมดถึงจะผสานถูกที่) · id ซ้ำกับใน
   comment → โจทย์เดิม: ข้ามหรือเสริมของเดิมเท่านั้น ห้ามนับเพิ่ม
3. ต่อข้อ สกัดบทเรียนแล้ว**ผสานเข้า section ที่ตรง** (แก้ของเดิม > เพิ่มของใหม่):
   - เทคนิคอ่านโจทย์/ตัดตัวเลือกแบบใหม่ → 1.1–1.4: เพิ่มแถวตาราง หรือ principle
     ใหม่ (ตั้งชื่อ bold) พร้อม "ตัวอย่างจริง:" จากโจทย์ข้อนี้
   - ความรู้เนื้อหา → section หมวด: อธิบายไทยง่าย ๆ ให้คนไม่เคยอ่านเฉลยเข้าใจเอง +
     **analogy เทียบของใกล้ตัว**เมื่อช่วยให้เห็นภาพ + **ตารางเปรียบเทียบ**เมื่อมี
     ของให้เทียบ + **decision table** "| โจทย์บอกว่า | ตอบ |" เมื่อเป็นเรื่องเลือกบริการ
     (2 คอลัมน์คือขั้นต่ำ — เพิ่มคอลัมน์ได้ตามเนื้อหา เช่น ประเภท/โปรโตคอล)
   - user บอกว่าตอบข้อนี้ผิด/เกือบพลาด → เพิ่มย่อหน้า "บทเรียนจากที่พลาด: …"
     ใน section ที่เกี่ยว
   - ศัพท์ใหม่ → อธิบายไทย inline ใน section ที่ใช้ ถ้าไม่เข้าหมวดไหน →
     ตารางศัพท์เบ็ดเตล็ด · คำที่เคยอธิบายแล้ว ไม่อธิบายซ้ำ
   - ได้เทคนิคที่ควรเช็คทุกข้อ → เพิ่มข้อใน Checklist ท้ายไฟล์
4. **Merge-first**: ความรู้ซ้ำกับที่มีอยู่ → เสริมของเดิม (เพิ่มตัวอย่าง/แถว/บรรทัด)
   ห้ามเขียนเรื่องเดียวกันสองที่ — ถ้าจำเป็นต้องอ้างข้ามให้ลิงก์หา section เดิม
5. **Currency check** — เทียบข้อเท็จจริง + service ในเฉลยกับ
   `docs/tickets/aws-currency-checklist.md` **ทั้งไฟล์** (ban list, §9 CONFLICT และ
   หมวดความรู้ที่โมเดลมักจำผิด): เฉลยใช้ service ที่ AWS ปิด/เปลี่ยน/แทนที่แล้ว → จดตามเฉลย
   แต่กำกับ `⚠ currency: ข้อสอบเฉลย X — ปัจจุบัน … ของจริงวันนี้คือ Y` ตรงจุดนั้น
6. อัปเดตหัวไฟล์ — **ห้าม +1**: recompute N = จำนวน id ใน comment `<!-- ids: -->`
   (เพิ่ม id ใหม่เข้า comment ก่อน) + เติมชื่อย่อโจทย์ + วันที่วันนี้
7. ตอบ user สั้น ๆ: ข้อไหนผสานเข้า section ไหน + ประเด็นเด็ดของข้อนั้น 1 บรรทัด —
   **ไม่มี quiz** แล้วเปิดให้ถามต่อ
8. **Follow-up loop (ห้ามข้าม)**:
   - ถามต่อ**เชิงเนื้อหา AWS/เทคนิคสอบ** → ตอบให้เข้าใจ แล้วจดลง `review-again.md`
     ทันทีโดยไม่ต้องรอสั่ง (template ด้านล่าง) · คำถามเชิง process/ไฟล์/git/รูปแบบโน้ต
     ตอบอย่างเดียว **ไม่จด**
   - จุดเดิมสะดุดซ้ำ → รายการเดิม: บวก `**เจอซ้ำ:** N` + อัปเดตวันที่ล่าสุด
     ไม่สร้างรายการซ้ำ · เรียงรายการตามตัวนับ มาก→น้อย
   - เพิ่มรายการแรก → ลบบรรทัด placeholder ในไฟล์ทิ้ง

- **ที่สงสัย:** <คำถามของ user แบบ paraphrase>
- **คำตอบสั้น:** <ไทย 2–4 บรรทัด พออ่านซ้ำแล้วเคลียร์>

## กติกาการเขียน

- ไทย + ศัพท์เทคนิคอังกฤษ · **เน้นอ่านเข้าใจง่ายเหนือความกระชับ** — ยอมยาวขึ้น
  เพื่อให้อ่านรู้เรื่องโดยไม่ต้องเห็นโจทย์/เฉลยต้นฉบับ
- สไตล์ตามที่มีอยู่ในไฟล์: ตาราง markdown จัด format ถูก (มีแถวคั่น `|---|`),
  analogy ภาษาคน, principle ตั้งชื่อ bold, ตัวอย่างจริงจากโจทย์
- **PARAPHRASE เท่านั้น** — ห้าม copy ข้อความโจทย์/เฉลยของ practice exam ตรง ๆ
  และห้ามเก็บตัวโจทย์เต็ม ๆ (ลิขสิทธิ์) — เก็บบทเรียนที่สรุปด้วยคำของเราเอง
- URL ใช้เฉพาะที่แนบมากับเฉลย หรือ official AWS docs ที่แน่ใจว่ามีจริง — ห้ามเดา URL
- ชื่อ service ไม่แน่ใจ → เช็ค docs.aws.amazon.com ประกอบ
  `docs/tickets/aws-currency-checklist.md`
- `notes.md` ยาวเกิน ~1,500 บรรทัดเมื่อไหร่ → เสนอ user แตกเป็นไฟล์รายส่วน
  (อย่าแตกเองโดยไม่ถาม)

## เมื่อไหร่ต้อง escalate (fable)

เฉลยดูขัดแย้งกันเอง / สงสัยว่าเฉลยผิด / เทคนิคซับซ้อนจนอธิบายไม่มั่นใจ / user ขอ
audit โน้ตทั้งชุด → ทำตาม escalation path ใน CLAUDE.md: **ขอ permission จาก user
ก่อนทุกครั้ง ไม่ใช่ routine** แล้วค่อย spawn one-off subagent `model: fable` พร้อม
โจทย์+เฉลยเต็ม ๆ เป็น context · ระหว่างรอ อย่าบันทึกสิ่งที่ยังสงสัยเป็นโน้ตปกติ —
กำกับ `⚠ ต้อง verify` ตรงจุดนั้นใน notes.md
