  corpus ที่มีจำนวนตัวเลือกต่างกัน ตัวเลข 33% ด้านล่างใช้ได้เฉพาะ corpus ที่ทุกข้อมี 3 ตัวเลือก
  (`recall_checks` เดิม); corpus ที่ใช้รูปแบบข้อสอบจริง 4 ตัวเลือก (เช่น AWS SAA-C03,
  ดู [`aws-cert.md`](aws-cert.md)) ต้อง**วัดกับ baseline 25%** ไม่ใช่ 33% — วัดผิด baseline คือ
  false-green แบบเดียวกับที่ #38 เคยพลาด (ดู "บทเรียนที่ 1" ด้านล่าง) เพียงแต่สลับมาที่ตัวส่วนแทน
  ตัวเศษ: corpus ที่เดาถูกจริง 33% จะรายงานผ่านถ้าเทียบกับ baseline 33% (3 ตัวเลือก) ทั้งที่ตัวมันเอง
  มี 4 ตัวเลือก และ 33% > 25% ของ baseline จริงคือ tell ที่วัดไม่เจอ — measurement script จึงต้อง
  parameterize baseline ตามจำนวนตัวเลือกของ corpus นั้น ไม่ hardcode 33%
- เดาด้วยกฎ "เลือกตัวเลือกที่ยาว/สั้น/กลาง" ต้องได้ ≈baseline (เท่าการเดาสุ่ม)

## บทเรียนที่ 1 — วัดให้ตรงโจทย์

รอบแรกตั้งกฎว่า "คำตอบที่ถูกห้ามยาวที่สุดและห้ามสั้นที่สุด" แล้ววัดว่ากฎถูกละเมิดไหม (ผ่าน 100%) แต่เมื่อมี 3 ตัวเลือก กฎนี้บังคับให้คำตอบเป็น "ตัวกลาง" เสมอ → เดาถูก 89.6%

**ตัวชี้วัดที่ถูกต้องคือ** "เดาด้วยกฎง่าย ๆ แล้วถูกกี่ %" ไม่ใช่ "กฎที่ตั้งไว้ถูกละเมิดไหม"

## บทเรียนที่ 2 — การเติมข้อความให้ distractor คือจุดเสี่ยงสูงสุด

วัดจริง:

- การ **ย่อ** distractor → error 0%
- การ **ต่อความยาว** distractor → error ~30% (31 จุดจาก 103)

**สาเหตุ**: การขยายมักกลายเป็นการ **ประดิษฐ์กลไกเชิงสาเหตุ** ที่บทไม่ได้พูดหรือขัดกับบท เช่น:

- ยก compaction (กลไกของ LSM-tree) ไปอธิบาย B-tree
- อ้างว่า ACID ทำให้ available มากขึ้น
- อ้างว่าตัวอย่างใน prompt เขียนทับ weight ของโมเดล

## กฎสำหรับการแก้ distractor ในอนาคต

เรียงตามลำดับที่ควรลอง:

### 1. ห้ามใช้คำเชื่อมเชิงสาเหตุในข้อความที่เติมใหม่

`เพราะ / เนื่องจาก / จึง / ทำให้ / ส่งผลให้` — ตรวจด้วย grep ได้ ต่างจากกฎ "ห้ามเพิ่มข้อเท็จจริงใหม่" ที่ตรวจอัตโนมัติไม่ได้

### 2. ขยายด้วยถ้อยคำจากหัวข้อ "เข้าใจผิดที่พบบ่อย" / "ขีดจำกัด" ของบทนั้นเอง

วิธีนี้วัดได้ว่า error 0%

### 3. ขยายแบบ บรรยายขอบเขตให้กว้างเกินจริง โดยไม่อธิบายว่าทำไม

### 4. escape hatch

ถ้าขยายอย่างปลอดภัยไม่ได้ ยอมให้ความยาว **เท่ากับคำตอบพอดี** (เสมอกัน = 50/50 ไม่ใช่ tell) ดีกว่าแต่งกลไกผิด

## กฎที่ต้องรักษาเสมอเมื่อแก้ MCQ

- ห้ามแก้ `expected_answer`, คำถาม, `body_md`, `references` — ทำให้พิสูจน์ได้ด้วย diff ว่าความรู้ที่ผู้เรียนได้ไม่เปลี่ยน
- คำถามแนว "ข้อใดคือความเข้าใจผิด/ข้อใดผิด" → distractor ต้องเป็นข้อความ **จริง** (ผิดพลาดซ้ำ 2 รอบเพราะข้อนี้)
- ห้ามคำเน้นสุดโต่ง (`เสมอ / ไม่ว่า...ก็ตาม / ไม่มีข้อยกเว้น`) กระจุกที่ตัวเลือกผิด → กลายเป็น tell แบบใหม่

## หนี้ที่ยังเหลือ (follow-up)

- distractor บางตัวถูกแทนด้วยข้อความที่ปลอดภัยแต่ **หลุดธีมของบท** (b-trees, column-oriented-storage, process-pauses) → ตัดทิ้งง่ายกว่าปกติ ควรขัดเกลาตอนทำ ticket ที่เพิ่ม `explanation` ต่อ MCQ ทุกข้อ (จะต้องอ่านทุกข้ออยู่แล้ว)
- ยังไม่มี **shuffle ตอน render** — ทำใน ticket ฝั่ง frontend เพื่อกัน tell เรื่องตำแหน่งถาวร
